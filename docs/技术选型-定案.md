# Mira Novel Studio 技术选型定案

> 2026-09-30 定稿 · 依据：`设计方案-现状对标与蓝图.md`、Mira-Harness 实际依赖（package.json 0.0.10）、`prototype/index.html` 交互原型。
> 原则：能复用宿主的不新造；每项选型给降级路径；本文件是决策记录，改动需更新此文件。

---

## 0. 结论速览

| 领域 | 定案 | 一句话理由 |
|------|------|-----------|
| 应用形态 | **Wujie 微应用**（纯渲染层），宿主 Electron 持有一切能力 | PRODUCT.md 既定架构；Studio 仓库零 Electron/node 依赖 |
| 框架 | **Vue 3.5 + TypeScript 5.7 + Vite 6** | 与 Harness 同栈同版本，设计令牌/组件经验直接复用 |
| 状态 | **Pinia 3**（业务态）+ preference API（UI 偏好） | Harness 同款；数据不入 Pinia 持久化，一律走 SQLite |
| UI 组件 | **Element Plus 2.14 + @iconify/vue（lucide 集）**，工作区组件自研 | 基础控件用现成；树/泳道/候选卡/上下文条等按原型自研 |
| 样式 | **SCSS + --cp 设计令牌**（从 Harness 复制单文件，标注来源） | 与原型一致；不引 Tailwind（Harness 的 Tailwind 只属 React 侧） |
| 正文编辑器 | **Milkdown 7.22（Crepe）**，配纯文本对照模式 | 已在 Harness 依赖且完成主题适配；MD 原生契合导出管线 |
| 数据层 | **better-sqlite3 13（宿主侧）按实体分表 + FTS5** | 数据归宿主；Studio 经 IPC 访问，不做本地副本 |
| 模型接入 | **复用 Harness 本地 SSE 代理 + 统一模型配置** | 密钥不出宿主；Studio 只拼 prompt、消费流 |
| Diff | **jsdiff 8（已在依赖）**，中文用 diffChars / Intl.Segmenter 词级 | 设计稿原写的 diff-match-patch 撤销——库里已有 jsdiff |
| 拖拽 | **vuedraggable 4.1（已在依赖）** | 设计稿原写的 vue-draggable-plus 撤销——库里已有等价物 |
| 检索 | M1：**FTS5 + 别名匹配（pinyin-pro 已有，顺带拼音首字母搜实体）**；M3 起：sqlite-vec + 本地 ONNX 嵌入 | 长篇前期关键词够用；向量是优化不是地基 |
| 测试 | **Vitest 3 + vue-tsc**，重点覆盖迁移器与上下文组装器 | 与 Harness 工具链一致 |
| 包管理 | **npm**（对齐 Harness），Studio 独立 git 仓库 | Harness 用 package-lock；互不污染依赖树 |

## 1. 应用形态与宿主边界（最重要的一个决定）

**Studio 是纯前端微应用，不含 Electron、不含 node 侧代码。** 边界如下：

```
Mira-Novel-Studio 仓库（本仓库）          Mira-Harness 仓库（宿主）
├─ Vue 渲染层（四个工作区+书架+向导）      ├─ Electron main：模型 SSE 代理、IPC、SQLite
├─ 纯 TS 领域模块：                        ├─ novelStore v2 / 迁移器 / FTS5（宿主侧数据层）
│   上下文组装器 · 摄取提案 · 一致性检查    ├─ wujie Shell：应用注册、主题、preference
│   （全部可 vitest 单测，不碰 DOM）        └─ 平台 API（preload 桥 + 类型契约）
└─ 平台 API 的类型契约（.d.ts，随宿主版本对齐）
```

- **归属宿主**：SQLite 读写、模型调用与密钥、文件导出落盘、EPUB 打包落盘。
- **归属 Studio**：prompt 组装、生成编排、diff 计算、全部 UI。密钥永不进入渲染层（PRODUCT.md 约束）。
- **装载方式**：照搬 `harness-react-app` 先例——Studio `vite build` 出静态产物，由 Harness 以 extraResources 装载、wujie 加载。Vite + wujie 的调试摩擦（publicPath/ESM）在 React 应用上已踩平，Vue 侧只会更顺。
- **演进预留**：若后续要独立沉浸写作窗口，宿主开一个 BrowserWindow 直载同一份产物即可，架构不变。

## 2. 前端栈细节

- **版本对齐**（与 Harness 一字不差）：vue ^3.5.13、element-plus ^2.14.2、pinia ^3.0.4、vue-router ^4.6.4（书架/工作台路由）、sass ^1.101、typescript ^5.7、vite ^6、vue-tsc ^2.2、vitest ^3.2.7。
- **设计令牌**：`tokens.scss` + 暗色 mixin 从 Harness 复制为单文件，文件头注明来源版本号；出现第三个消费方时再抽 `@mira/design-tokens` 包，现在不抽。
- **图标**：统一 `@iconify/vue` + lucide 集（原型的手绘内联 SVG 是设计稿，不是实现方案）。
- **中文工具**：`pinyin-pro`（已在 Harness 依赖）做实体搜索的拼音首字母匹配——白捡的能力。
- **i18n**：首版仅中文；文案不硬编码在组件里，集中在 `src/locale/zh-CN.ts`，为将来留缝但不做运行时 i18n。

## 3. 编辑器

- **主线：Milkdown Crepe**（`@milkdown/crepe` + `@milkdown/kit` 7.22，均已在依赖）。理由：MD 原生（导出/快照/上下文注入全是 MD）、ProseMirror 底子可扩展（选区内联操作、批注）、Harness 已踩平主题变量。
- **纯文本模式保留**：对照模式/专注模式切换到无装饰 textarea，既是性能逃生舱也是部分用户的偏好（对标现有 NovelMarkdownEditor 的双模式）。
- **打字机模式**：CSS `scroll-padding` + 光标跟随滚动实现，不引依赖。
- **决策依据**：wangEditor-next 虽也在 Harness 依赖里，但它是 HTML 底子，与 MD 导出管线之间要多一层 turndown 转换且格式有损——不用于正文。markdown-it（渲染 AI 输出预览）与 turndown（其余模块 HTML↔MD）在宿主侧照旧。
- **长章节性能预案**：单场景以 3-5k 字为主（网文章节天然分块），Milkdown 无压力；若用户粘贴超长文，导入流程强制分章拆分，不给编辑器塞十万字的机会。

## 4. 数据层（宿主侧，本仓库只定契约）

- **Schema v2**：`projects / volumes / chapters / scenes / entities / snapshots / ai_runs` 分表，替代 v1 整项目 JSON payload；一次性迁移器 + v1 导入兼容（迁移器是 vitest 第一优先级用例）。
- **FTS5 中文**：`unicode61` 按字切分即可满足"实体名/关键词命中"，配合 aliases 表做精确匹配；**不引jieba 等分词扩展**（native 依赖越少越好）。
- **快照**：AI 应用前自动写入 `snapshots` 表（内容 + reason + createdAt），回收站语义基于快照实现。
- **版本化导出**：全量 JSON 导出保持 `version: 2` 字段，向后兼容 v1 导入。

## 5. AI 管线

- **通道**：复用 `electron/adapters/novelApi.ts` 的本地 SSE 代理模式，扩展为按任务路由（draft/summary/extract → automation 便宜模型；正文/审校 → authoring 强模型）。任务路由表放宿主配置。
- **结构化输出**（实体提取、一致性检查）：优先 JSON Schema 约束，**必须带降级**——小模型输出不规范时回退到分隔符文本协议解析 + 本地校验，绝不因模型能力差而崩流程（对标调研中 NovelForge 的教训）。
- **中断/重试**：AbortController 全链路透传；失败自动重试一次，再失败交还用户。长任务（整卷生成）落宿主任务表，可暂停恢复。
- **上下文组装器**（Studio 侧纯 TS）：分层优先级 + token 预算裁剪，输入全部来自 IPC 数据切片；纯函数设计，快照测试覆盖。

## 6. 按里程碑引入的依赖（只买当下要用的）

| 里程碑 | 新增 | 说明 |
|--------|------|------|
| M1 | （零新增，全部复用 Harness 已有） | milkdown、jsdiff、vuedraggable、pinia 均已在库 |
| M2 | 无新增 | FTS5 是 SQLite 内建 |
| M3 | `sqlite-vec` + `onnxruntime-node` + bge-small-zh-v1.5 int8（约 30MB，随 extraResources 分发） | 本地语义检索；做不进就不上，关键词版兜底 |
| M4 | `jszip`（EPUB 手拼 OPF）；关系图优先 Canvas/SVG 自绘，不够再评估 sigma.js | epub-gen 系已停更，不碰 |

## 7. 工程与质量

- **仓库**：Mira-Novel-Studio 独立 git 仓库（当前目录即工作目录）；npm；`engines.node` 与 Harness 对齐。
- **CI 门禁**：`vue-tsc --noEmit` + `vitest run` + `vite build` 三件事，全绿才许合并。
- **测试重点**：v1→v2 迁移器、上下文组装器（分层裁剪）、摄取提案解析、diff 段落对齐——这四块是正确性敏感区，UI 不追求覆盖率。
- **AGPL 合规**：对标项目（NovelForge/QMAI/goink/AI_NovelGenerator 等）均为 AGPL，只参考机制设计，禁止复制代码；本仓库 MIT。

## 8. 明确不做的事（负面清单）

- ❌ 不引 Tailwind / 未样式化组件库（与 Harness Vue 侧风格冲突）
- ❌ 不做 Electron 壳、不做独立安装包（宿主已有）
- ❌ 不在渲染层存 API Key、不直连模型厂商
- ❌ M1-M2 不上向量检索、知识图谱、Neo4j（关键词 + 结构化注入先跑通）
- ❌ 不引入状态机库/工作流引擎（生成编排用显式 TS 状态即可，对标 NovelForge 的"代码式工作流翻车"教训）
- ❌ 不做运行时 i18n、不做协同编辑、不做移动端

## 9. 风险与预案

| 风险 | 概率 | 预案 |
|------|------|------|
| Milkdown 对超长/异常格式文档表现不稳 | 中 | 纯文本模式兜底已内建；导入强制分章 |
| wujie + Vite 调试体验差 | 中 | 照抄 harness-react-app 的装载与 publicPath 处理；最坏情况宿主开独立窗口直载产物 |
| 小模型结构化输出不可靠 | 高（已默认会发生） | 分隔符文本协议降级 + 本地校验，见 §5 |
| better-sqlite3 native 重编 | 低 | 宿主已有 electron-rebuild 流程，Studio 无 native 依赖 |
| 需求膨胀回"全自动生成器" | 高 | 负面清单 §8 + 里程碑纪律：每个 M 交付可用的写作闭环，而不是生成管线的一段 |
