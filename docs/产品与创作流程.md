# 产品与创作流程

更新：2026-11-03。本文替代历史设计稿。产品方向由作者确认：作者主导的完整工作台；本地只浏览，真实能力依托 Mira App。

## 1. 小说如何持续写下去

不存在适用于所有小说的唯一创作顺序。这里选用“全书方向粗、近期章节细、写后事实回流”的工作法，允许作者从正文起步、再补蓝图，避免把创作变成强制问卷。

| 阶段 | 作者先决定什么 | 应产生什么 | 进入下一步前检查 |
| --- | --- | --- | --- |
| 想法 | 谁想要什么，遭遇什么变化，为什么值得读 | 作品名、一句话核心、可选开篇方向 | 有一个能推动行动的矛盾即可 |
| 蓝图 | 主角目标、弱点、阻力、关系、世界规则、视角与语言 | 可修改的故事背景、人物、关系、主线、写作约定 | 方向与叙事边界由作者认可 |
| 全书规划 | 起点、关键转折、终点或尚待解决的问题 | 粗粒度全书脉络 | 不把预测的剧情当已发生事实 |
| 近期章纲 | 本章目标、障碍、事件转折、结尾交接 | 接下来少量章节的细纲 | 不必一次写死整本书 |
| 正文 | 本章要实现什么，读者此刻知道什么 | 手写正文或 AI 候选稿 | 作者读过候选；AI 不直接覆盖正文 |
| 审阅 | 保留什么、改哪里，是否符合角色与事实 | 按段采纳或保留原文 | 原文版本仍与提案基线一致 |
| 定稿与记忆 | 本章真正发生了什么、发生了哪些变化 | 作者确认的章节摘要和来源指纹 | 正文版本匹配后才标记已定稿 |
| 下一章 | 上章结果怎样改变人物选择 | 新一章的任务和上下文 | 使用有效前章记忆；前章改写后摘要失效 |

“审阅”在本版指作者审阅 AI 修改与摘要，并不等同于自动质量审稿。专门的多维质量检查、问题定位及自动修复预算尚未实现。全书完稿后的结构回看、语言统稿、导出发布属于后续产品设计，当前没有虚设可点击入口。

## 2. 为什么需要确认点

完整流程不是重复调用同一提示词。每一步都需要明确输入、产物、状态与后续消费者：章纲是计划，正文是稿件，摘要是对已发生内容的解释，只有作者确认才作为章节记忆。

- AI 结果单独保存为待审阅提案，不直接覆盖正文或章纲。
- 作者可以逐个变更段选择采纳；拒绝保留原文。
- 原文发生变化时，旧正文或章纲提案不能静默覆盖新稿。
- 记忆提案基于正文内容指纹。正文变化后，旧摘要不再注入后章；必须重新整理并确认。
- 已接受和拒绝的提案可以查看或清理。当前没有完整版本历史或自动快照。

## 3. 页面分工

| 页面 | 主要任务 |
| --- | --- |
| 我的作品 | 找到作品、回到创作；无作品时提示开书 |
| 新建作品 | 暂定书名、一句话想法、首章方向；创建空白首章 |
| 创作蓝图 | 维护全书背景、人物、关系、主线与写作约定 |
| 章节规划 | 全书脉络、逐章展开、章纲编辑、AI 细化提案 |
| 正文写作 | 章目录、稿件、伴写与实际上下文预览；可切换专注模式 |
| 设定与记忆 | 维护角色、地点、规则；查阅已确认章节摘要 |
| 审阅 | 原文/建议对比、按段选择、确认或拒绝、记忆定稿 |
| Mira 连接 | 连接状态、拟议模型选择和职责边界 |

## 4. 上下文规则

当前使用保守的字符预算，不声称是模型 token。优先保留写作约定、本章任务、当前正文，再纳入上章结尾、全书蓝图和设定/有效摘要。界面展示实际进入预算的文本。若正文被截取会标注；尚未实现基于模型窗口的 tokenizer、语义召回或向量检索。

全书蓝图可以描述未来方向，但不作为已发生事实。章节摘要只取当前章之前、来源正文指纹匹配的记录。角色和世界规则由作者维护，当前没有字段级事实图谱或秘密可见性规则。

## 5. 当前完成标准

本轮交付是重写文档、重建可浏览原型、开发页面与待接入客户端。Mira 当前没有开放对应存储和模型方法；真实作品创建、保存和生成必须等宿主按显式契约实现后再验收，不能用浏览器示例替代。
